## 0. 이 문서의 범위
- 승인된 R-ID만 기준으로 **논리 모델**을 정한다. DB 제품, 물리 테이블, 인덱스, 저장 형식은 3단계에서 정한다.
- 특정 전략의 고유 지표는 핵심 모델에 넣지 않는다 (ENT-12 근거 레코드로 분리).
- 브로커 고유 상태·필드의 매핑은 키움 사양 확인(U-07) 후 3단계에서 정한다. 여기서는 브로커 중립 상태만 쓴다.
- [v0.8 CP-024] M2(바이낸스 현물 테스트넷)의 상태·필드 매핑은 승인된 CP-024 결정과 BN v0.3 근거로 2-M2 부록에 둔다. 물리 스키마 변경은 3단계 문서와 구현 작업(T-M2-04·05·06·08)에서 정하며, M1 PAPER-1 중간에는 적용하지 않는다(CP-024 §2.1).

### 2.2 정밀도와 반올림 (D-032)
[v0.8 CP-024] 공통 단위는 **계좌 기준 통화(ENT-01)와 십진수(Decimal)**다. 가격·수량·금액의 자릿수와 맞춤 방향은 시장별 규칙이며, 아래 표의 "M1 규칙" 열은 M1 값 그대로이고 2-M1 부록 값과 같다(다른 문서가 "02 §2.2"로 M1 규칙을 참조하므로 열을 옮기지 않았다). M2 규칙은 2-M2 부록 표(D-118)에 둔다.

| 대상 | M1 규칙 (= 2-M1, 변경 없음) | 공통 원칙 |
|---|---|---|
| 가격 | KRW 정수. 호가 단위 규칙은 키움·KRX 사양 [미확인, 3단계] | 계좌 기준 통화의 십진수. 브로커가 받는 단위·자릿수로 저장 (시장 부록) [v0.8 CP-024] |
| 수량 | 정수 주. 산정 시 내림 (00 §2.8) | 십진수. 시장의 수량 단위로 산정 시 내림. M2는 거래소 수량 단위(stepSize, 2-M2) [v0.8 CP-024] |
| 체결 금액 | 가격 × 수량, 정확한 값 | 반올림 없음. 브로커가 체결 금액을 보고하는 시장은 보고값을 확정값으로 쓴다(M2, D-118) [v0.8 CP-024] |
| 비용(수수료·세금) | 추정값은 원 미만 **올림** (보수적). 확정값은 브로커 값 그대로 | 추정·확정 구분 필드 필수. 추정은 시장 자릿수에서 올림(보수적) [v0.8 CP-024] |
| 주문 가능 현금 계산 | 원 미만 **내림** | 보수적 방향 |
| 비율(한도 사용률·손실률) | 비교는 반올림 전 값으로. 표시만 소수 4자리 | 한도 비교 전에 반올림하지 않음 |
| 통화 | M1은 KRW만 | 금액 필드는 통화를 항상 가짐. 계좌(시장)마다 단일 기준 통화, 시장 간 환산·합산 한도 없음(A-055). M2는 USDT [v0.8 CP-024] |

### 3.2 필드 정의
공통 필드는 모든 엔티티에 있다: `모드`(열거, 필수, INV-12), `생성 시각`(시각, 필수). 아래 표에서는 생략한다.

**저장소 메타** [v0.8 CP-024 D-097]: 저장소(DB) 하나에 레코드가 아닌 메타로 `모드`, `market`(M1 / M2 / M3), `broker`(예: `kiwoom-mock`, `binance-spot-testnet`)를 둔다.
- 새 저장소는 생성 시 기록한다.
- 엔진·운영 도구는 저장소를 열 때 메타가 실행 설정(모드·market·broker)과 다르면 거부한다(03 D-090의 "저장소는 처음 만든 모드에 묶임"을 시장까지 확장, INV-12).
- 메타가 없는 기존 M1 저장소: 설정이 M1이면 스키마 전진 마이그레이션으로 `M1`·`kiwoom-mock`을 1회 기록한다(백업 선행 03 D-060, M1 PAPER-1 중간 금지). 설정이 M2면 거부한다.
- 앱 설정에 market·broker 키가 없으면 `M1`·`kiwoom-mock`으로 본다(M1 설정 파일 변경 없음).

## 4. 멱등키 (D-030)
| 요청 출처 | 멱등키 구성 | 효과 |
|---|---|---|
| 전략 신호 | 신호 ID (결정적, 00 §2.5) | 같은 신호 재도착·재시작 후 재판정 → 같은 키 → 의도 추가 생성 안 됨 (E-2) |
| 운영 요청 | (채널, 채널 메시지 ID). 로컬 명령은 명령 실행 ID | 메신저 메시지 중복 수신 → 1회만 |
| 정지 정책 취소 | (정지 ID, 대상 브로커 주문 ID) | 정지 재평가로 같은 취소 반복 안 됨 |
| 실행 정책 취소·정정 | (대상 브로커 주문 ID, 정책 규칙, 발동 차수) | 미체결 정책의 같은 단계 반복 안 됨 |

- **생성 시점**: 게이트가 승인하는 순간, 의도·한도 예약·소유권 예약과 **같은 저장 단위**로 영속한다 (01 D-022, R-25).
- **범위**: 계좌 + 모드. 모드가 다르면 저장소가 다르다 (D-036).
- **보존**: 의도와 같은 기간 (감사 5년). 재시작 후에도 조회 가능해야 한다.
- **브로커 멱등성**: 가정하지 않는다. [v0.3 CP-011] 키움은 고객 주문 식별자를 지원하지 않음을 확인했다(broker-specs/kiwoom-kr.md §3). D-029(종목·방향당 활성 의도 1개)로 조회 매칭이 유일하다.
- [v0.8 CP-024 D-110] **M2**: 고객 주문 ID(ENT-16)를 멱등키에서 결정적으로 만들어 보내지만, 서버의 중복 ID 거부를 멱등성으로 보지 않는다(BN §5). -2010 중복 메시지("Duplicate order sent."·"The clOrdId is already in use.")는 결과 불명으로 보고 그 ID로 조회한다(D-112). D-029·INV-15는 M2에도 그대로 적용한다.
