### 1.1 토큰 갱신을 직접 볼 수 없다 (코드 확인, 2026-10-14)
- 갱신 규칙: 만료 10분 전부터 다음 조회 때 새로 발급(`broker/kiwoom/token.py` `REFRESH_BEFORE = 10분`). 시세 조회가 주말에도 1.2초마다 돌아 이 조회가 갱신을 일으킨다.
- **v0.1 시점(코드 변경 전)에는 발급·갱신 성공이 어디에도 기록되지 않았다**(메모리 카운터만). **A-099 Q-1로 추가**: 발급 성공마다 감사 기록 `TOKEN_ISSUED`(ref = 계좌 별칭, 요약 `reason` INITIAL·REFRESH·REISSUE, `expires_at`, `previous_expires_at`, `count` — 토큰 값 없음), REFRESH(만료 전 갱신)는 텔레그램 INFO "토큰 갱신 (만료 …)"도 보낸다. 실패는 종전대로:
  - 발급 3회 실패 → K5 + 긴급 알림 "브로커 치명 오류 … — K5", "토큰 발급 실패 N회".
  - 인증 오류(8005)는 조회 재시도 안에서 재발급으로 넘어가면 흔적 없음. 3회 모두 실패해야 WARNING "시장 데이터 조회 연속 실패 … 8005 (AUTH)"·"대조 조회 실패".
- **실패 가능성 하나[미확인]**: 키움이 재발급 요청에 아직 유효한 같은 토큰(만료 시각 그대로)을 돌려주면, 만료 10분 이내라 `token.py`가 "만료 시각이 너무 가까움"으로 거부 → 3회 실패 → K5 + "브로커 치명 오류 … — K5" 긴급 알림이 실제 만료 때까지 이어지고, 만료 뒤 새 토큰으로 회복할 수 있다. 이 실행이 그것을 시험하는 셈이다 — 이 알림이 오면 결함 후보로 기록한다(주문 없음, 위험 아님).
- O-1 판정: **직접** — 토·일에 `TOKEN_ISSUED` REFRESH 행(직전 만료 = 앞 토큰의 만료, 새 만료 ≈ +24시간)과 텔레그램 "토큰 갱신". **보조** — 예상 갱신 시각 전후 `quote_poll_stat` 실패 0, 토큰·인증 관련 알림 0. 금요일 run의 INITIAL 행이 없으면 코드가 반영되지 않은 것이다(§4.3에서 확인).
- 코드가 목요일 밤까지 main에 병합되지 않으면 v0.1처럼 보조 증거만으로 판정한다(A-099 ②).

## 3. 시작 전 점검 (금요일, 사용자)
1. 텔레그램 "일일 요약"(금요일분)을 받았는지 본다. 안 왔으면 시작하지 말고 에이전트에게 알린다.
2. **Windows Update 일시 중지(권장)**: 설정(`Windows 키 + I`) → "Windows 업데이트" → **"1주 동안 일시 중지"**. 금·토 밤 23:00~05:00 재시작이 run을 끊는 것을 막는다. 월요일 이후 "업데이트 다시 시작"을 눌러 해제할지는 사용자 판단(보안 업데이트 지연과 맞바꿈). 일시 중지하지 않으면 재시작 시 run이 끝나며, 그 결과도 기록한다.
3. 절전 "안 함"(사용 설명서 §2.5) 유지 확인.
4. PowerShell 창을 연다(시작 메뉴 → "Windows PowerShell", 관리자 아님). 아래를 붙여 넣는다:
```
cd C:\AI\trading_system\trading_system
.venv\Scripts\python scripts\status.py --mode PAPER
```
기대 결과: `보유 포지션`은 0건 — **단 2026-10-16(금)에는 전략(paper0-verify:2) 소유 005930 1주가 남아 있어도 된다**(10-15 직접 매수 시험으로 14:30 매도가 K4에 막힘, 07 §12G; 주말 run은 K8을 풀지 않아 주문 없음. 직접 매수분 1주는 금요일 장중 매도·저녁 정리 끝난 뒤 시작), `미체결 주문: 0건`, `결과 불명 의도: 0건`, `열린 대조 불일치: 0건`, `KILL 파일: 없음`, 하트비트 줄은 "멈춤 의심"(run이 꺼져 있다는 뜻 — 정상). 정지는 K9(paper0-verify v1 교체) 1건만. **하나라도 다르면 시작하지 않고** 출력 전체를 에이전트에게 보낸다.

## 4. 시작 (금요일 T0, 사용자)
### 4.1 시작 점검
같은 창에서:
```
$env:TRADE_MODE='PAPER'
.venv\Scripts\python scripts\preflight.py
```
기대 결과: `토큰: 발급 (만료 …), 폐기 완료` 줄과 마지막 `결과: 통과`. **이 만료 시각을 적어 둔다**(토큰 수명 실측값 — 발급 시각과의 차이). 시작 점검은 자기 토큰을 끝에 폐기하므로 run 토큰과 별개다. "실행 잠금 보유"로 거부되면 금요일 자동 운영이 아직 안 끝난 것이다 → 10분 뒤 다시.

### 4.2 run 시작
같은 창에서(이 창은 일요일 정지 때까지 닫지 않는다, 창 안을 클릭하지 않는다 — 클릭하면 "빠른 편집"으로 멈출 수 있다):
```
$env:TRADE_MODE='PAPER'; $env:PYTHONPATH='src'; .venv\Scripts\python -m trading_system.app run
```
기대 결과: 시작 출력 뒤 `K8 재개: scripts/resume.py --mode PAPER K8` 안내가 나오고 계속 실행된다. 텔레그램에 "정지 K8 발동: 프로세스 시작" 긴급 알림이 온다(정상).
- **K8을 풀지 않는다.** K8이 걸려 있으면 어떤 주문도 나가지 않는다(전략 판정 건너뜀, 취소·운영 요청까지 거부 — `domain/halts.py`). 주말 관찰(토큰·날짜 경계·시계·실시간)은 K8과 무관하게 돈다. 시작 시각을 에이전트에게 알려 주면 예상 갱신 시각을 기록한다.
- 이 수동 run은 콘솔 출력을 파일로 남기지 않는다. 경고·긴급은 `var\paper\logs\ops-YYYYMMDD.jsonl`과 DB에도 남으므로 따로 저장할 필요는 없다.

### 4.3 시작 직후 확인 (두 번째 PowerShell 창)
```
cd C:\AI\trading_system\trading_system
.venv\Scripts\python scripts\status.py --mode PAPER
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object { $_.CommandLine -like '*trading_system.app run*' } | Select-Object ProcessId, @{n='MB';e={[math]::Round($_.WorkingSetSize/1MB)}}, CreationDate
(Get-Item .\var\paper\trading.db).Length
```
기대 결과: `status` 하트비트 "N초 전"(30초 미만), 해제되지 않은 정지에 K8·K9. 둘째 명령은 **2줄**이 나온다 — `.venv` python은 실행기라서 실제 파이썬을 자식으로 하나 더 띄운다. **MB가 큰 쪽**이 run이다(번호·메모리 MB·시작 시각). 셋째는 DB 크기(바이트). 세 값을 적어 두거나 에이전트에게 보낸다(O-5). 같은 세 명령을 토·일에 한 번씩, 정지 직전에 한 번 더.
- 시작 뒤 에이전트에게 "TOKEN_ISSUED 확인"이라고 하면 DB를 읽기 전용으로 조회해 이번 run의 INITIAL 행(만료 시각)을 확인한다. 없으면 감사 기록 코드가 반영되지 않은 것이다(보조 증거로 진행).

## 5. 주말 중 (사용자, 선택)
- 휴대폰 텔레그램 `/status`로 상태를 볼 수 있다. 예상되는 알림: 토·일 08:00·16:00 "일일 보고"(INFO), 토·일 저녁 시작 시각 10~20분 전 "토큰 갱신 (만료 …)"(INFO), 실시간 끊김이면 "정지 K5 발동"(긴급) → 재접속 뒤 "자동 해제". **K5·K6 알림은 주문이 없는 시간이라 위험이 아니다** — 무시하고 기록만.
