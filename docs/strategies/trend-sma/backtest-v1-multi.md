- **L6**: 전략은 SMA20 > SMA60인 동안 매일 진입 신호를 낸다(상태 진입, Q3). 30종목 중 상승 추세 종목이 3개를 넘으면 나머지는 매일 L6으로 거부된다. 거부는 위험 확대 차단으로 정상 동작이지만, **어느 종목을 보유할지가 전략 규칙이 아니라 신호 처리 순서(종목코드 오름차순 — 스냅샷 종목 목록이 정렬됨)로 정해진다**. TRAIN 거래 수: 000270 17, 005490 17, 005380 16, 000810 12, 000660 11 … 316140·207940 각 1, 298040·329180·373220·402340·034020 0.
- **L7 (기본 9건)**: 전략은 판정 시세(그날 시가) × 1.3으로 L7 수량을 정하고, 게이트는 상한가(전일 종가 × 1.3, 100원 단위 내림)로 주문 금액을 평가한다. 시가가 전일 종가보다 낮은 날 100만 원을 약간 넘어(예: 1,000,200원) 거부. 그날 진입이 없어질 뿐 위험 확대는 없다.
- **L1 (참고 실행)**: 게이트 L1 = (예약 가격 − 손절가) × 수량, 시장가의 예약 가격 = **상한가**(gate.py `_reserve_price`, 03 §6.2·01 D-020). 전략 S-3 위험 크기는 (기준가 − 손절가)로 계산하므로, 상한가와 기준가의 차이(약 30%)만큼 게이트가 본 손실이 커진다. 예: 000270 159주 × 48,300원 → 게이트 손실 2,666,748원 > 한도 500,000원. 기본 실행에서는 L7(100만 원)이 수량을 작게 묶어 이 차이가 드러나지 않았다. → **운용 규모를 키우려면 L7 완화만으로는 안 되고, 전략 크기 산정 기준(상한가 기준 위험)과 L1 정의를 맞추는 결정이 필요**하다(Q3).

## 부록 B. 구동기가 시스템 CLI와 다른 점
`python -m trading_system.app backtest`와 같은 `run_backtest`·`perturbation_check`를 쓰되 다음만 다르다.
1. 달력: 2016~2023 추출 휴장일을 실행 안에서 추가(CLI는 `config/calendar`만 읽어 2024 이전은 "달력 없음"으로 거부).
2. 유니버스: 전략 코드의 `spec.universe = ("005930",)`를 데이터 폴더 30종목으로 실행 중 객체만 교체. **전략 코드는 U-A 목록이 005930 하나이므로, 30종목으로 PAPER에 쓰려면 목록 변경 = 버전 올림(strategy.md §가정)**.
3. 한도: 기본 실행은 저장소 `config/limits.backtest.toml` 그대로. 참고 실행만 var/ 사본 + 전략 L7 상수 교체.
4. 민감도: CLI `run_sensitivity`는 구간을 ALL로 바꿔 FINAL 기간까지 돌리므로 쓰지 않고, 구간을 유지한 0·2틱 실행을 따로 했다.
5. 룩어헤드 검사: CLI와 같은 검사일 목록을 검사일별 프로세스로 나눠 실행.
6. 보고서: 시스템 `render_report` 대신 결과 JSON·DB를 이 문서로 정리.
