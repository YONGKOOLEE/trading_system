### 2.6 안전 검토
- **상태 변경 거부는 위험을 늘리지 않는다.** 교체 중지가 거부되면 v1은 원래 승인 상태(PAPER)로 남아 승인된 규칙대로 운용된다(현 상태 유지). 새 주문 경로·새 허용은 없다. 시작 거부는 엔진을 만들기 전 설정 오류이므로 브로커 주문이 없다.
- **거부되었을 때 사람이 할 수 있는 것** (01 §2.5·§2.6 근거):
  1. v1을 그대로 운용해 v1의 감액·청산 규칙으로 무보유가 된 뒤 교체(00 §2.11 개정안 3). paper0-verify v1은 같은 날 14:30 판정에서 청산한다(시험으로 확인).
  2. 바로 멈춰야 하면 v1을 **사용자 판단 중지(USER)**로 전이(보유 중에도 허용) → K9: 해당 전략 신규·증액 차단, 해당 전략 매수 미체결 취소, 보유 유지, 감액·청산은 **운영 요청만**(01 K9 "사용자 판단" 행, `halt_rejection`은 운영 요청 OPERATOR를 변형과 무관하게 허용). 01 §2.5 감액·청산 행 "소유 전략(또는 운영 요청)". 무보유 뒤 폐기(DP-11) → v2 활성.
  3. 계좌 전체를 멈춰야 하면 K1(수동 킬 스위치): 신규·증액 차단, 운영 요청의 감액·청산·취소 허용, 자동 청산 없음.
- **시작 거부의 비용**: 고아 보유가 있는 배포 설정으로는 그날 엔진이 돌지 않으므로 다른 전략의 판정·청산 신호도 나가지 않는다. 대신 사용자는 원인(전략·건수)을 시작 메시지로 받고 설정을 되돌리면 된다. 현재 M1 PAPER 배포는 전략 1개라 추가 비용은 작다. 경고만 하고 시작하는 대안은 고아 보유를 계속 두는 것이라 기각(DP-49).
- **자동 청산 없음 원칙 유지**: 어느 경로도 v1 보유를 자동으로 팔지 않는다.

### 2.7 오늘 배포에 대한 영향
- `config/app.paper.toml`: paper0-verify v2(PAPER) 배포, v1은 2026-10-07 교체 중지(A-067 B-5, 보유 0건 확인 뒤) → v1은 사유 REPLACE·무보유이므로 시작 검사를 통과한다(같은 형태를 `test_v279_flat_replaced_owner_may_stay_undeployed`·`test_v180_switch_when_flat_*`로 확인).
