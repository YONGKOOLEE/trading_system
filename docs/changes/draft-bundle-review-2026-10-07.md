## 5. 승인 뒤 에이전트가 할 일 (사용자 승인 후에만)
1. 승인 범위를 `docs/approvals.md`에 새 A-ID로 전사 — 문서명·**승인 버전 명시**·포함 CP·제외 범위(실전 주문 코드·LIVE 아님).
2. 승인 문서 머리말: 상태 `draft` → `approved`, 승인 A-ID·날짜, 낡은 머리말(§3 #4·#7·#8) 정정. 승인 문구와 다른 내용은 고치지 않음.
3. archive: 기존 승인본 사본(§0 목록)은 이미 있음 — 해당 파일 머리말 또는 README에 `superseded` 표기만. 승인 직후 다시 개정할 문서(예: CP-028 미반영 상태로 승인한 01·03·04)는 새 승인본을 archive에 보존한 뒤 새 draft 생성.
4. `docs/.status` 게이트 행 갱신(버전·A-ID), `last_updated`·주석 정정. `docs/README.md` 표 갱신.
5. CP 상태 갱신: CP-025 머리말 `approved (A-xxx)`. capabilities.md는 2차 질문 3의 조건 충족 뒤 개정안으로 교체.
6. 커밋: 문서 변경 커밋은 사용자 지시 시(CLAUDE.md §5; A-030은 문서 로컬 커밋 허용 기록 — 적용 범위는 사용자 확인). push 없음.
