## 1. CP-017 Q3 — 시세 신선도 기준 권장값

| 항목 | 내용 |
|---|---|
| 권장값 | **60초** (PAPER-0·PAPER-1 초기값). PAPER-0에서 실제 조회 주기를 잰 뒤 조정 |
| "시세 시각"의 정의 (제안) | 시스템이 브로커에서 그 가격을 **받은 시각**(조회 응답 수신 시각). 01 §2.7 "최근 시세 시각"을 이렇게 해석한다. 이유: M1 설계의 실시간 구독(D-050: 00·04·1h·0s·0g)에 체결 시세가 없어 시세는 REST 조회(ka10001 등)로 얻고, 그 응답에 체결 시각이 있는지 미확인 |
| 근거 1 — 조회 주기 | 모의투자 호출 제한은 **TR당 1초 1회**(kiwoom-kr §2, 확인). 시세 TR 하나로 감시 종목 N개를 돌면 갱신 주기 ≈ N초. M1 초기 감시 종목을 20개 이하로 보면 주기 ≤ 20초. 한 번 조회가 실패(최대 3회 재시도, 03 §5.3)해도 거부가 남발되지 않으려면 주기의 약 3배 = 60초 |
| 근거 2 — 영향 범위 | 시장가 매수 예약은 상한가 기준(03 §6.2)이라 가격이 조금 오래돼도 노출을 적게 잡지 않음. 신선도가 지키는 것은 주로 (a) 시세 공급 장애 감지, (b) 보유 평가(L2·L3·L4)의 정확도 |
| 더 짧게(10~30초) | 조회 주기와 겹쳐 정상 상황에서도 위험 확대 거부가 잦아짐. 실시간 체결 시세(WS) 구독을 설계에 추가하면 가능 → 구독 추가는 설계 변경(D-050) |
| 더 길게(5분) | VI·급변 직전 가격으로 평가할 위험. 5분 판정 주기 전략에서는 판정 1회분이 통째로 오래된 가격 |
| 확인 방법 | PAPER-0에 "시세 조회 주기·지연 측정" 항목 추가(PV, 제안 D-9). 측정 주기 × 3이 60초를 넘으면 값 재결정 |
| 설정 위치 | 한도 설정 파일(`config/limits.<mode>.toml`)에 `quote_max_age_seconds` 추가 — T-010에서 스키마 반영(기본값 없음, 누락 시 시작 거부) |
