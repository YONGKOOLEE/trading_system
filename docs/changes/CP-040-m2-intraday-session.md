## 7. 안전 검토
- **주문 경로 하나**(§8-2): 손절 감시는 신호 원천만 하나 더한다 — 청산 요청 → 게이트 → 실행기 → 어댑터 → 대조·기록 그대로. 거래소 대기 주문(스톱)은 만들지 않는다(D-264).
- **전략은 신호만**(§8-1): 전략은 손절가를 신호에 싣고 능력을 선언할 뿐, 감시·주문은 시스템. 집계 봉·확장 열은 읽기 전용 스냅샷으로만 전달.
- **요청 유형 구분**(§8-3): 손절 청산은 감액·청산 유형으로 01 §2.6 정지 표를 그대로 따른다 — 위험 축소에 위험 확대와 같은 거부를 걸지 않되, 새 예외도 만들지 않는다.
- **결과 불명**(§8-6): 손절 청산이 결과 불명이면 해소 전까지 새 요청 없음, 미해소면 K3·사람 확인.
- **자동 재전송 없음**(§8-7): IOC EXPIRED·손절 미체결 뒤 같은 요청을 다시 보내지 않는다. 다음 닫힌 봉에서 새로 판단한 요청만(새 의도, 감사 기록). 백필 조회는 횟수·분당 상한·실패 시 신호 무효로 끝난다.
- **정지는 청산이 아님**(§8-8): K2·K1 발동이 손절 감시를 "전량 청산"으로 바꾸지 않는다. 손절 감시는 전략이 선언한 손절가에서만.
- **재시작 직후 주문 금지**(§8-9): K8 동안 손절 청산 없음 — 대조·복구 뒤 재개. 그 사이 노출은 남은 위험(D-263 (8)).
- **불확실하면 주문하지 않음**(§8-10): 결측·품질 실패 분은 손절 판단 안 함, 집계 봉 결측은 채우지 않음, 이력 부족은 신호 무효.
- **모드·환경 분리**(§7): 손절 감시·집계는 PAPER에서 테스트넷(또는 CP-039 승인 시 공개 시세 읽기 전용) 데이터만. 실서버 주문 경로 없음. 공개 CSV는 백테스트에서만 읽음.
- **위험이 늘어나는 곳**: (1) 판정·감시 횟수 증가로 주문 수 증가 → L5·주문 창·호출 예산 시작 검사. (2) 장중 L4 측정(백테스트)으로 K2가 자주 보이게 됨 — 실제 운영도 이미 연속 측정이라 K2·사용자 재개 빈도가 늘 수 있음(알림 피로, 평일 낮 텔레그램 `/resume K2`) — 값 결정 때 V-334 통계로 본다. (3) 손절 감시 단절(프로세스 사망) 동안 보호 없음 — LIVE 전 D-264 재검토.
