## 9. 안전 검토
- **실서버로 가는 것은 공개 GET뿐**: 키·서명·계좌·주문 경로를 구조적으로 막는다 — 모듈에 자격정보 인자 없음(V-315), 가드가 헤더·서명 쿼리·허용 밖 경로를 전송 전 거부(V-314), 실행 출처 `RunGuard`는 실서버 호스트를 계속 거부(V-316). 주문 경로(CLAUDE.md §8-2)는 하나 그대로이고 실행 출처는 테스트넷뿐이다.
- **모드 값만 바꿔 실전 접속 불가**(CLAUDE.md §7): 시작 표 LIVE 행 없음(실행·데이터 모두), 데이터 출처 행은 PAPER·M2·읽기 전용만.
- **위험 확대만 더 엄격, 위험 축소는 그대로**(§8-3): 괴리·신호 출처 지연은 신규 진입·증액만 거부. 신호 출처 장애 중에도 포지션 유지(§8-8)와 사람 청산 요청 가능.
- **불확실하면 진입하지 않음**(§8-10): 참조 시세가 없거나 늙거나 괴리가 크면 진입 거부. 출처를 섞어 메우지 않는다(D-254 (5)).
- **자동 재시도 없음**(§8-7): 괴리 거부 진입은 재전송하지 않고, 실서버 429·418은 즉시 중단.
- **IP 공유 위험(남은 위험)**: 실서버 IP 가중치가 사용자 수동 매매와 합산될 수 있다([미확인]). 별도 저예산·429 즉시 중단으로 줄이지만 0은 아니다 — 418 차단은 같은 IP의 사용자 API 사용에 영향을 줄 수 있다.
- **해석 위험**: PAPER 손익이 "실서버 신호 + 테스트넷 체결" 혼합이라 오독될 수 있다 — 지표 분리·표시(D-251·D-255), 성과는 계속 판정 제외.
- **M1 무영향**: 공통 코드 변경은 설정이 없을 때 동작 불변(V-326) + M1 전체 회귀.
- **승인 구조**: 이 CP 승인 ≠ 구현 착수 ≠ 실서버 공개 시세 연결 승인(T-064) ≠ 테스트넷 주문 승인 ≠ 실전 주문 코드 승인 ≠ LIVE 실행 승인.
