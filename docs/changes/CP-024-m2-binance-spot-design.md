## 0. 요약
- M2는 **별도 체크아웃 디렉터리에서 도는 별도 프로그램**이다(A-061). M1과 DB·잠금·KILL 파일·비밀 설정·텔레그램 봇이 모두 갈리고, 정지도 시장별이다(A-062②, A-063⑧).
- 주문 경로·게이트·결과 4분류·정지 체계(K1~K11)·대조 원칙은 M1과 같다. 다른 것은 **수량(소수·수수료 차감·dust)**, **시간(24/7·UTC 일 경계)**, **브로커 계약(고객 주문 ID·필터·가중치 제한·오류 코드)**, **대조 범위(자산별 잔고·USDT 현금)** 네 가지다.
- 공통 문서 본문이 바뀌는 곳은 §3 표의 "공통 예" 행이다. 승인되면 M1 승인(업무정의서·00·01·02·03·04)과 관련 V 항목을 재검토한다. **M1 코드도 바뀐다**(일반화). M1 동작은 같게 유지하는 것이 목표이고, 각 작업에서 M1 전체 회귀 시험으로 확인한다.
- **착수 순서** [결정 A-065 Q1]: M2 첫 작업은 최소 종단 간 흐름(T-M2-01, fake 브로커)이고, 공통 코드 일반화가 필요하므로 M1 T-017 뒤에 시작한다.
- **시세 지연 중 청산** [결정 A-065 Q4 — 위임 결정, 사용자 재확인 대기]: 현 규칙(G11)상 시장가 청산이 막히므로, M2는 시세 지연 중 감액·청산을 IOC 지정가 매도로 한다(D-120).

### 2.2 정상 흐름 (M2)
1. 시작: 모드·market·broker·도메인·DB 메타 일치(D-097·D-098) → 바이낸스 서버 시각(D-115) → exchangeInfo(규칙·rateLimits, D-106·D-113) → 계좌 조회 → 대조(D-103·D-109) → K8 재개 대기(M1과 같음).
2. 판정: 일 경계 뒤 1d 봉 확정(D-108) → 전략 신호 → 게이트(G1~G15, G10 = 거래 규칙, G11 = 시세 신선도, G12 = 24/7 + 주문 창).
3. 수량: 목표 금액 ÷ 주문가 → stepSize 내림 → 필터 사전 검사(D-106) → 실패면 게이트 거부(전송 0).
4. 전송: 고객 주문 ID(D-110) 포함 IOC 지정가 매수 또는 시장가 매도 → 4분류(D-112).
