## 0. 이 문서의 범위
- 매매전략은 아직 정하지 않았다(업무정의서 §0). 앞으로 어떤 전략이 추가될지도 알 수 없다.
- 그래서 이 문서는 특정 전략이 아니라 **모든 전략이 따라야 하는 형식, 계약, 등록 절차**를 정한다.
- 원칙: 시스템은 **고정 코어**와 **확장 지점**으로 나눈다. 전략이 요구하는 능력을 시스템이 아직 지원하지 않으면, 코어를 고치지 않고 확장 지점에 기능을 추가한다(2026-10-01 대화 합의 방향. 이 문서 승인으로 확정).
- 이 문서에서 정하지 않는 것: 설정 스키마의 물리 필드, 기술 스택(3단계), 리스크 수치(1단계), 백테스트 합격 기준(4단계).

## 1. 결정 사항
D-ID는 문서 전체에서 일련번호를 쓴다. 0단계는 D-001부터 시작한다.

## 2. 본문 — 시장 공통

### 2.1 용어
| 용어 | 뜻 |
|---|---|
| 전략 | 등록 명세와 규칙으로 정의되고 신호만 내는 모듈. (전략ID, 버전)으로 식별 |
| 판정 | 전략을 한 번 실행해 신호를 산출하는 일. 판정 트리거에 따라 일어남 |
| 판정 기준 시각 | 판정에 사용한 데이터의 기준 시각(as-of). 이 시각 이후의 데이터는 쓰면 안 됨 |
| 신호 | 판정의 출력. 게이트에 들어가는 요청 중 하나(다른 하나는 운영 요청 R-21) |
| 능력(CAP) | 시스템이 전략에 제공하는 기능 단위. 트리거·데이터·주문 유형·상품 등 |
| 유니버스 | 전략이 판정할 수 있는 종목 집합 |
| 위험 확대 / 위험 축소 | 진입·증액 / 감액·청산 |

### 2.2 전략 규칙 형식 (D-001)
전략의 모든 규칙을 아래 표 한 행으로 쓴다. 한 행이 판정 가능하지 않으면 등록할 수 없다.

| 항목 | 작성 내용 | 예시(형식 설명용이며 전략이 아님) |
|---|---|---|
| 규칙 ID | 전략 안에서 고유 (예: `ENTRY-1`) | ENTRY-1 |
| 규칙 종류 | 진입 / 증액 / 감액 / 청산 / 재진입 제한 | 진입 |
| 입력 | 사용하는 데이터와 상태. CAP-ID로 표기 | 일봉 종가 (CAP-DAT-01), 보유 여부 (상태 입력) |
| 판정 시점 | 판정 트리거. CAP-ID로 표기 | 장 마감 후 정해진 시각 (CAP-TRG-01) |
| 조건 | 결정 가능한 논리식. 아래 조건 종류를 조합 | 보유 없음 AND 지표 A > 지표 B |
| 행동 | 낼 신호 종류와 크기 산정 방법(§2.8) | 진입, 크기 방식 S-2 |
| 무효 조건 | 신호를 내지 않는 경우 | 필요한 봉 수 부족, 데이터 품질 실패 |
| 우선순위 | 같은 종류 규칙끼리의 순위. 종류 간 순서는 D-006으로 고정 | 3 |

조건 종류:
| 종류 | 예 | 입력 출처 |
|---|---|---|
| 수치 | 가격, 지표, 거래량의 비교 | 시장 데이터 (R-22 품질 검사를 통과한 것) |
| 포지션 상태 | 보유 여부, 보유 수량, 보유 기간(거래일), 평균단가 대비 손익률 | 시스템이 제공하는 읽기 전용 스냅샷 |
| 거래 이력 | 이 전략의 해당 종목 직전 청산 시각·청산 사유(규칙 ID / 운영 요청 / 정지 정책), 최근 N거래일 진입 횟수. 재진입 제한 규칙의 입력 | 읽기 전용 스냅샷. 전략·버전별로 제공 |
| 주문 상태 | 해당 종목에 처리 중인 주문 의도나 미체결이 있음 | 읽기 전용 스냅샷 |
| 거래 상태 | 거래정지, VI, 상·하한가, 관리종목 (R-27) | 읽기 전용 스냅샷 |
| 이벤트 | 새 봉 확정, 체결 발생, 장 시작·마감, 유니버스 변경 | 판정 트리거가 전달 |
| 시각·달력 | 장 마감 N분 전, 보유 N거래일 경과 | 판정 기준 시각과 시장 달력 (R-14) |

판정 규칙:
- 입력이 누락되었거나 품질 검사에 실패하면 그 종목은 신호를 내지 않는다. 기본값으로 채우지 않는다 (R-22).
- 전략은 판정 기준 시각 이후의 데이터를 받지 않고, 받을 수 없어야 한다. 룩어헤드 방지는 입력을 공급하는 쪽이 보장한다 (R-10, 방법은 3단계).
- 전략은 결정적이어야 한다 (D-002). 백테스트와 PAPER가 같은 코드와 같은 전처리 규칙을 쓴다 (R-22).
- 전략 고유의 지표와 중간값은 신호의 "근거" 필드에만 담는다. 핵심 데이터 모델과 분리한다 (2단계).

### 2.3 능력 목록 (D-003, D-004) [제안]
전략이 요구할 수 있는 능력의 목록이다. "지원 여부"는 이 문서에서 정하지 않는다. 첫 구현 범위(5단계)와 첫 전략이 정해질 때 함께 정한다. 목록은 필요할 때 CP(변경 제안, `docs/changes/`)로 늘린다.

- **지원 목록의 위치**: 시장별 CAP 지원 상태(지원 / 미지원 / 검증 중, 근거 T-ID·검증 항목)는 `docs/capabilities.md`에 둔다. 이 문서 승인 후 모든 항목을 "미지원"으로 만들고, 5단계와 구현 완료 시점에 갱신한다. 등록 검증(§2.13)은 이 목록을 기준으로 한다.

| 분류 | CAP-ID | 능력 | 영향을 받는 코어 검사 |
|---|---|---|---|
| 판정 트리거 | CAP-TRG-01 | 정해진 시각 (예: 장 마감 후 1회) | 거래 시간, 신호 유효 기한 |
| | CAP-TRG-02 | 주기 (예: 장중 N분마다) | 시세 신선도, 호출 제한 |
| | CAP-TRG-03 | 시세 이벤트 (가격이 들어올 때마다) | 시세 신선도, 동시 신호, 호출 제한 |
| | CAP-TRG-04 | 체결 이벤트 (내 주문이 체결되면) | 주문 상태 스냅샷의 일관성 |
| 데이터 | CAP-DAT-01 | 일봉 (수정주가 여부 명시) | 데이터 품질 (R-22), U-06 |
| | CAP-DAT-02 | 분봉 | 데이터 품질, 저장량 |
| | CAP-DAT-03 | 실시간 체결가 | 시세 신선도, 연결 단절 처리 |
| | CAP-DAT-04 | 호가 | 시세 신선도 |
| | CAP-DAT-05 | 비시세 데이터 (재무·공시·지수 등) | 출처·기준 시각 기록 |
| 주문 가격 유형 | CAP-ORD-01 | 시장가 | 가격 유효성, 슬리피지 가정 |

### 2.6 신호 유효 기한 (D-007)
- 전략 명세에 기한 산정 규칙을 반드시 적는다. 예: "판정 기준 시각 + N분", "다음 거래일 장 시작 후 N분까지".
- **절대 상한**: 모든 신호의 기한은 판정 기준 시각 + 전략 명세의 최대 경과 시간을 넘을 수 없다. 모든 트리거 유형에 적용한다.
- 시각·주기 트리거(CAP-TRG-01·02)는 추가로 기한이 **다음 예정 판정 시각보다 늦을 수 없다**. 새 판정이 이전 신호를 대신한다.
- 이벤트 트리거(CAP-TRG-03·04)는 다음 판정 시점을 미리 알 수 없으므로 절대 상한만 적용한다. 같은 종목의 새 판정이 나오면 이전 신호를 대신한다.
- 기한이 지난 신호는 게이트가 거부한다. 이미 브로커에 전송된 주문은 기한 만료로 자동 취소하지 않는다. 미체결 처리는 실행 정책(CAP-ORD-03)을 따른다.
- 신호 기한과 시세 신선도(R-04)는 별개의 검사다. 둘 다 통과해야 한다.

### 2.7 복수 신호 처리
| 상황 | 처리 | 근거 |
|---|---|---|
| 같은 전략, 같은 판정, 같은 종목에서 여러 규칙이 충족됨 | 전략이 우선순위로 1개만 냄 | D-006 |
| 같은 전략, 같은 종목에 처리 중인 주문 의도가 있는데 새 신호가 옴 | 위험 확대 신호는 거부. 위험 축소 신호는 게이트가 요청 유형별 규칙으로 판정(1단계에서 상세화) | R-05, R-06 |
| 같은 신호가 다시 도착함 | 중복으로 거부 | R-05, E-2 |
| 여러 전략이 같은 종목에 신호를 냄 | 종목 배타 소유. 다른 전략이 소유(예약 포함) 중이면 진입 거부. 소유하지 않은 전략의 증액·감액·청산 신호도 거부 | D-008 |
| 여러 종목의 신호가 동시에 와서 합산 한도를 넘음 | 게이트가 예약 순서대로 판정하고 한도를 넘는 신호를 거부. 같은 판정 배치 안에서는 위험 축소 먼저, 그다음 전략 명세의 순위, 그다음 종목코드 순서로 정해 결과가 매번 같게 함 | R-04, CLAUDE.md §8-4 |

종목 배타 소유 (D-008):
- 한 시장에서 한 종목의 포지션은 한 번에 한 전략만 가진다.
- 다른 전략이 보유 중인 종목에 대한 진입 신호는 거부하고 사유를 기록한다.
- 소유권은 게이트가 진입을 승인할 때 **예약**된다. 예약은 노출 예약과 같은 원자적 단계에서 이루어진다 (CLAUDE.md §8-4). 그래서 체결 전 미체결 구간에 다른 전략이 같은 종목에 진입할 수 없다.
- 소유권이 풀리는 경우: (1) 전량 청산 확정, (2) 진입 주문이 **체결 0주로 종결 확정**(거부·취소·만료가 조회로 확인됨). 일부만 체결되고 종결되면 보유분이 있으므로 소유권이 유지된다.
- 결과 불명 상태에서는 예약도 소유권도 풀리지 않는다 (R-06).
- 외부 수동 거래(E-6)로 생긴 차이는 대조 불일치로 처리하며, 소유권은 사람이 정한다(업무정의서 §6-9).

### 2.8 포지션 크기 산정 틀
전략은 아래 방식 중 하나를 고르고, 수치는 전략 파라미터로 정한다.

| 방식 | 내용 | 필요한 입력 |
|---|---|---|
| S-1 고정 금액 | 1회 진입 금액을 고정 | 기준 가격 |
| S-2 비율 | 계좌 기준 금액의 X% (분모 정의는 1단계 U-02) | 계좌 기준 금액, 기준 가격 |
| S-3 위험 기반 | (1회 허용 손실액) ÷ (진입가 − 손절가). 손절 규칙이 규칙 표에 있어야 함 | 손절가, 1회 최대 손실(R-04) |
| S-4 고정 수량 | 수량을 고정 | — |

- 수량은 시장의 수량 단위에 맞게 **내림**한다. 결과가 0이면 신호를 내지 않는다. 금액·수량에 이진 부동소수를 쓰지 않는다 (업무정의서 §9).
- 감액 크기는 보유 수량 이하, 청산은 보유 전량으로 한다. 보유 수량을 넘는 매도는 거부한다 (공매도 금지).
- 전략이 계산한 크기는 요청값일 뿐이다. 최종 허용은 게이트가 판단한다 (D-009).

### 2.9 제외 범위
- 레버리지 차입, 신용, 마진, 미수, 공매도, 파생, 선물은 제외한다.
- 결과적으로 보유 수량이 0보다 작아지는 신호, 주문 가능 현금을 넘는 매수 신호는 거부한다.
- 레버리지·인버스 **ETF/ETN**은 상품 안에 레버리지가 들어 있는 것으로, 차입 레버리지가 아니므로 허용한다 (D-013). 현물 매수·매도만 하며 위의 제외 규칙은 그대로 적용된다.

### 2.10 사람의 종목 선정 경계 (D-012)
| 유니버스 방식 | 내용 | 경계 |
|---|---|---|
| U-A 고정 목록 | 전략 명세에 종목을 적음 | 목록을 바꾸면 전략 버전을 올림 |
| U-B 사람이 제출한 목록 | 사람이 파일로 제출. 제출 시각, 제출자, 목록 버전을 기록 | 판정 입력으로만 쓰임. 다음 판정부터 적용 |

- [제안] 보유 중인 종목이 목록에서 빠지면 신규 진입·증액만 막고, 보유분은 전략의 청산 규칙대로 둔다. 자동으로 청산하지 않는다.

|---|---|---|
| 초안 → 백테스트 통과 | 4단계 백테스트 기준 충족 보고 (`backtest-v<n>.md`) | 사용자 |

버전 교체 절차 (같은 시장에서 v1 → v2):
1. v2는 초안부터 시작해 v1과 같은 상태(예: PAPER 중)까지 따로 승인받는다. 그동안 v1은 그대로 운용한다.
2. 사용자가 교체를 승인하면 v1을 **중지(사유: 교체)**로 바꾸고, v2를 목표 상태로 바꾼다.
3. v1의 보유 종목은 v1이 계속 소유한다. v1의 감액·청산 규칙으로 처리하는 것을 기본으로 한다 [제안]. 중지 사유가 "교체"일 때 위험 축소 신호를 허용할지는 1단계 정지 정책 표에서 확정한다.
4. v2는 v1이 소유한 종목에 진입할 수 없다(D-008). v1의 소유권이 모두 풀린 뒤 v1을 폐기할 수 있다.
5. 보유분을 v2로 넘기는 **소유권 이전**은 지원하지 않는다. 필요하면 CP로 별도 제안한다.
- 킬 스위치(R-07)는 계좌 수준의 정지이고 전략 상태를 바꾸지 않는다.

### 2.12 실패 국면 가설 틀
전략마다 아래 표를 채운다. 가설이지 예측이 아니다.

| 항목 | 작성 내용 |
|---|---|
| 국면 이름 | 예: 추세 없는 횡보, 변동성 급등, 유동성 저하, 갭이 잦은 구간 |
| 판별 지표 | 사후에 계산할 수 있는 관측값과 기준 |
| 예상 실패 양상 | 잦은 손절, 큰 슬리피지, 미체결 증가 등 |
| 검증 방법 | 백테스트 구간을 국면별로 나눠 성과를 비교 (4단계) |
| 운영 대응 | 이 국면에서 사람이 중지를 검토하는 기준. 자동 전환은 하지 않음 (D-010) |

### 2.13 전략 추가 절차
1. `docs/strategies/<전략ID>/strategy.md`를 부록 A 양식으로 작성한다.
2. 필요 능력을 `docs/capabilities.md`의 해당 시장 지원 목록과 비교한다. 지원하지 않는 능력이 있으면 CP(`docs/changes/CP-xxx.md`)를 작성해 기능 추가를 먼저 승인받는다.
3. 파라미터 값을 `config/strategies/`에 둔다 (R-19).
4. 등록 검증: 명세 누락, 파라미터 범위 밖, 능력 미지원이면 거부한다 (E-8, E-9).
5. 백테스트 → 상태 전환 승인 → PAPER → … (§2.11).
