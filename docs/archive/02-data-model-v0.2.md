## 0. 이 문서의 범위
- 승인된 R-ID만 기준으로 **논리 모델**을 정한다. DB 제품, 물리 테이블, 인덱스, 저장 형식은 3단계에서 정한다.
- 특정 전략의 고유 지표는 핵심 모델에 넣지 않는다 (ENT-12 근거 레코드로 분리).
- 브로커 고유 상태·필드의 매핑은 키움 사양 확인(U-07) 후 3단계에서 정한다. 여기서는 브로커 중립 상태만 쓴다.

## 1. 결정 사항

|---|---|---|---|

| D-029 | [제안] (Q-1 결정) **(계좌, 종목, 방향)마다 활성 의도는 최대 1개**다. 활성 = 종결되지 않은 상태 전부(결과 불명 포함). 브로커가 고객 주문 식별자를 지원하지 않아도 조회 결과를 의도와 유일하게 짝지을 수 있게 하기 위함 | R-05, R-06, U-07(미확인) | 여러 개 허용: 결과 불명 해소 때 같은 종목·방향 주문을 구별할 근거가 없을 수 있음 |
| D-030 | 멱등키는 **요청 출처별**로 정한다 (§4). 멱등키는 게이트 승인과 같은 저장 단위에서 의도와 함께 저장하고, 의도와 같은 기간 보존한다 | R-05, R-25 | 전송 시점 저장: 저장 전 장애 시 중복 가능 |

| D-032 | 금액·가격·수량은 십진수로 다루고 이진 부동소수를 쓰지 않는다. 반올림 규칙은 §2.2 | 업무정의서 §9 | — |

| D-035 | 포지션은 **내부 원장(체결 누적)**으로 계산하고, 브로커 잔고는 대조 스냅샷으로만 저장한다. 둘이 다르면 내부 원장을 브로커에 맞춰 자동 수정하지 않고 대조 불일치(K4)로 처리한다 | R-08, 01 §2.6 K4 | 브로커 잔고를 원장으로 사용: 불일치 원인(누락 체결·외부 거래)을 찾을 수 없음 |
| D-036 | 모든 엔티티에 **모드(BACKTEST/PAPER/LIVE)** 필드를 두고 저장소 모드와 같아야 한다 (INV-12). 저장소 자체도 모드별로 분리한다 | R-01 | 모드 필드 없이 저장소 분리만: 잘못 연결된 저장소를 탐지할 수 없음 |

## 2. 공통 규칙

### 2.1 논리 타입
| 타입 | 뜻 |
|---|---|
| ID | 시스템이 만드는 불투명 식별자. 형식은 3단계 |
| 외부ID | 브로커·메신저가 준 식별자. 원문 보존, 로그 마스킹 규칙은 3단계 |
| 열거 | 정해진 값 중 하나 |
| 정수 | 부호 있는 정수 |
| 십진수 | 이진 부동소수가 아닌 십진 수 |
| 금액 | 십진수 + 통화 코드 |
| 시각 | 시간대 확정 절대 시각 (D-031) |
| 거래일 | 시장 현지 날짜 |
| 참조 | 다른 엔티티의 ID |
| 해시 | 내용 해시 (설정·명세 버전 식별) |
| 목록 | 같은 타입 값의 순서 있는 모음 |

### 2.2 정밀도와 반올림 (D-032)
| 대상 | M1 규칙 | 공통 원칙 |
|---|---|---|
| 가격 | KRW 정수. 호가 단위 규칙은 키움·KRX 사양 [미확인, 3단계] | 브로커가 받는 단위로 저장 |
| 수량 | 정수 주. 산정 시 내림 (00 §2.8) | M2는 거래소 수량 단위 |
| 체결 금액 | 가격 × 수량, 정확한 값 | 반올림 없음 |
| 비용(수수료·세금) | 추정값은 원 미만 **올림** (보수적). 확정값은 브로커 값 그대로 | 추정·확정 구분 필드 필수 |
| 주문 가능 현금 계산 | 원 미만 **내림** | 보수적 방향 |
| 비율(한도 사용률·손실률) | 비교는 반올림 전 값으로. 표시만 소수 4자리 | 한도 비교 전에 반올림하지 않음 |
| 통화 | M1은 KRW만 | 금액 필드는 통화를 항상 가짐 |

### 2.3 민감도
| 등급 | 뜻 | 예 |
|---|---|---|
| 상 | 저장 금지 | 계좌번호, 앱키, 시크릿, 토큰 — 이 모델에 필드 없음. 계좌는 별칭만 (CLAUDE.md §6) |

## 4. 멱등키 (D-030)
| 요청 출처 | 멱등키 구성 | 효과 |
|---|---|---|
| 전략 신호 | 신호 ID (결정적, 00 §2.5) | 같은 신호 재도착·재시작 후 재판정 → 같은 키 → 의도 추가 생성 안 됨 (E-2) |
| 운영 요청 | (채널, 채널 메시지 ID). 로컬 명령은 명령 실행 ID | 메신저 메시지 중복 수신 → 1회만 |
| 정지 정책 취소 | (정지 ID, 대상 브로커 주문 ID) | 정지 재평가로 같은 취소 반복 안 됨 |
| 실행 정책 취소·정정 | (대상 브로커 주문 ID, 정책 규칙, 발동 차수) | 미체결 정책의 같은 단계 반복 안 됨 |

- **생성 시점**: 게이트가 승인하는 순간, 의도·한도 예약·소유권 예약과 **같은 저장 단위**로 영속한다 (01 D-022, R-25).
- **범위**: 계좌 + 모드. 모드가 다르면 저장소가 다르다 (D-036).
- **보존**: 의도와 같은 기간 (감사 5년). 재시작 후에도 조회 가능해야 한다.
- **브로커 멱등성**: 가정하지 않는다. 키움이 고객 주문 식별자를 지원하면 멱등키에서 파생해 보낸다 [미확인, U-07]. 지원하지 않아도 D-029(종목·방향당 활성 의도 1개)로 조회 매칭이 유일하다.
