- 버전 v0.1 (2026-10-08, **draft**) — 3일차 아침 자동 운영 결과까지 반영. 16시 이후 3일차 결과(15:45 종료·일일 요약)를 반영해 v0.2로 고친다.
- 대상: 사용자(운영자). 터미널 명령은 **복사해 붙이는 전체 명령**으로 적는다.
- 범위: **M1 PAPER(키움 모의 서버)만**. LIVE(실전 계좌)는 이 설명서의 범위가 아니며 자동화하지 않는다.

## 0. 용어
| 말 | 뜻 |
|---|---|
| 자동 운영(autopilot) | 하루 전체를 맡는 프로그램. 시작 점검 → 매매 프로그램(run) 실행 → K8 자동 재개 → 15:45 종료·집계·백업 → 일일 요약 |
| run | 실제로 시세를 보고 주문을 내는 매매 프로그램 |
| 시작 점검(preflight) | 키움 접속·조회·시계 오차를 확인하는 점검. 통과해야 run이 켜진다 |
| 대조 | 키움의 주문·체결·잔고와 시스템 기록이 같은지 비교하는 것. 같으면 MATCH |

| 예약 작업 | Windows 작업 스케줄러에 등록해 평일 아침 자동으로 켜지게 하는 것 |
| 모의 서버 실행 | 키움 모의투자 서버에 주문하는 것. 실제 돈이 오가지 않는다. "실전"은 LIVE에만 쓴다 |

## 2. 처음 한 번 — 예약 등록

1. 3일차(2026-10-08) 일일 요약까지 정상으로 끝났다 (에이전트가 결과를 확인한 뒤 등록을 안내한다).

## 4. 이상할 때
원칙: **판단이 어려우면 아무것도 하지 않는 쪽이 안전하다.** 그날 매매가 없을 뿐이다. 시스템은 불확실하면 주문하지 않게 만들어져 있다.

| # | 증상 | 뜻 | 할 일 |
|---|---|---|---|
| ① | 06:50이 지나도 "run 시작"이 없음 | 설정 오류(모드 줄·텔레그램 설정)로 시작하지 못함. 알릴 수단이 없어 로그에만 남음 | 그날은 매매 없음. 퇴근 후 Claude에게 "오늘 자동 운영 로그 봐 줘" — 에이전트가 `var\paper\logs\autopilot-YYYYMMDD.log`를 확인 |
| ② | "K8 자동 재개 실패" 또는 "사람 확인 정지 K…" | 대조 불일치 등으로 자동으로 풀 수 없음 | `/review`로 사유 확인 → 원하면 `/resume K8`(또는 `/resume K4`) → 답으로 온 `/confirm 코드`를 60초 안에. 거부되면 그날은 매매 없음 |
| ② | 08:55 "자동 재개 못 함 — 오늘 매매 없음" | 자동 재시도가 끝남 | 아무것도 안 해도 됨. 퇴근 후 Claude에게 알림 |
| ③ | 09:35에 보유 0건 | 09:30 매수가 안 됨 | `/review` 결과를 Claude에게 보냄. v2는 14:30에 매수하지 않으므로 `/kill` 필요 없음 |
| ④ | 14:35에 보유 1건 | 매도가 막힘 | 정지 사유를 Claude에게 보냄. 다음 날 14:30에 다시 매도를 시도함(자동 청산 없음) |
| ⑤ | 16:30까지 일일 요약이 없음 | 자동 운영이 도중에 멈춤 | 퇴근 후 §6.1 "오늘 run 끝내기" 전에 Claude에게 상태 확인 요청 |
| ⑥ | "run 프로세스가 종료됨"·"하트비트 멈춤" 긴급 알림 | run이 장중에 멈춤(자동 재시작 없음) | 그날 남은 매매 없음. 보유 중이면 다음 날로 넘어감. 퇴근 후 Claude에게 |
| ⑦ | 장중 K4 알림 | 대조 불일치 | `/review`로 확인 → 불일치 0건이 된 뒤 `/resume K4` → `/confirm 코드`. 거부되면 저녁에 PC에서 |
| ⑧ | 07:50~09:00 K5 알림 | 키움 모의 서버의 연결 끊김(매일 있을 수 있음) | 아무것도 안 함. 09:35에 풀렸는지 확인 |

**긴급 정지**가 필요하면 텔레그램 `/kill`(K1, 신규 매수 차단 — 청산 아님). 자동 운영은 K1을 스스로 풀지 않는다. 다음 날 아침 전에 풀려면 `/resume K1` → `/confirm 코드`.

## 5. 원격
### 5.1 텔레그램 명령 (매매 프로그램 봇)
| 명령 | 하는 일 | 확인 코드 |
|---|---|---|
| `/review` | 오늘 체결·정지·결과 불명·불일치·마지막 대조 (계좌번호·금액 없음) | 없음 |
| `/status` | 정지 목록·KILL 파일·결과 불명·불일치 건수 | 없음 |
| `/kill [사유]` | K1 긴급 정지 (즉시) | 없음 |
| `/resume K1`·`K2`·`K4`·`K8` | 정지 재개. K4·K8은 그 자리에서 새로 대조해 완전 일치할 때만 | 필요 |
| `/reconcile` | 즉시 대조, 결과 회신 | 필요 |
| `/exit`·`/reduce`·`/cancel` | 청산·감액·취소 요청 (중앙 게이트를 거침) | 필요 |

원격으로 **풀 수 없는** 정지: K3(결과 불명)·K7(저장 실패)·K9(전략)·실행기가 건 K4 → PC에서. 불일치 해소(`reconcile-resolve`)도 PC에서만.

### 5.2 Claude 원격 (분석·개발 지시)
1. 집 PC VS Code의 Claude 대화창에 `/remote-control` 입력 (출발 전).
2. 회사에서 브라우저 claude.ai/code 또는 휴대폰 Claude 앱 Code 탭 → 집 PC 세션 선택.
3. PC나 VS Code가 꺼지거나 30분가량 네트워크가 끊기면 연결이 끊긴다 → 퇴근 후 다시 `/remote-control`.

대화로 지시하면 에이전트가 할 수 있는 PAPER 운영 명령(A-079): 시작·정지·정지 재개 명령 기록·status·paper-review·backup. **하지 않는 것**: LIVE 일체, 실전 주문, 불일치 해소 방법 선택, 결과 불명 확정, KILL 파일 삭제, 예약 작업 등록·해제, 지시 없는 시작·재개.

## 6. 끄고 켜기
모든 명령은 일반 PowerShell에서 먼저 `cd C:\AI\trading_system\trading_system`.

### 6.1 오늘 run 끝내기 (장중이든 장 뒤든)
```
.venv\Scripts\python scripts\ops-stop.py --mode PAPER
```
기대 결과: "정지 요청 파일 작성" → "run 종료 확인". 자동 운영이 이어서 집계·백업·요약을 한다. 창 X 버튼이나 작업 관리자로 끄지 않는다.

### 6.2 하루만 쉬기
작업 스케줄러에서 `TradingSystem-PAPER-Autopilot`을 오른쪽 클릭 → "사용 안 함". 다음 날부터 다시 쓰려면 "사용".

### 6.3 하루만 손으로 (오늘 아침처럼 화면을 보며)
06:45 전에 PowerShell 창 하나에서 (창은 15:45 이후 끝날 때까지 닫지 않는다):
```
cd C:\AI\trading_system\trading_system
$env:TRADE_MODE='PAPER'
.venv\Scripts\python scripts\autopilot.py --mode PAPER
```
이미 자동 운영이 돌고 있으면 "run이 이미 실행 중"으로 아무것도 하지 않는다(두 번 켜지지 않는다).

### 6.4 완전히 그만두기 (관리자 권한 PowerShell)
```
cd C:\AI\trading_system\trading_system
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\schedule-unregister.ps1
```
기대 결과: 두 작업 "해제", "남은 TradingSystem-PAPER- 작업: 0개". 오늘 이미 돌고 있는 run은 멈추지 않는다 → 필요하면 §6.1.

### 6.5 PC를 재부팅했을 때
재부팅 뒤 **로그인만 하면** 다음 평일 06:45에 다시 실행된다. 장중에 재부팅됐다면 그날 run은 멈춘 상태다(자동 재시작 없음). 그날은 매매 없음으로 두는 것이 기본이다. 다시 켜고 싶으면 §6.3. 재시작 직후에는 K8이 걸리고, 대조가 끝난 뒤에야 주문이 다시 가능하다.

## 8. 전략 바꾸기
전략 변경은 **승인이 필요한 작업**이라 혼자 하지 않는다. 순서:
1. Claude에게 원하는 전략을 말한다 → 에이전트가 전략 문서·백테스트를 만든다.
2. 사용자가 백테스트 결과를 보고 승인한다.
3. **보유 0건인 날 저녁**에 바꾼다(보유는 전략 버전 사이에 넘어가지 않는다). 에이전트가 설정을 바꾸고, 사용자가 실행할 `strategy.py` 명령을 사본으로 미리 시험한 뒤 안내한다.
4. 다음 날 아침 텔레그램에 K9(이전 버전 중지) 경고가 오는 것은 정상이다.

## 9. 하지 말 것
- run이 돌고 있는 동안 시작 점검(preflight)이나 run을 한 번 더 실행.
- 실행 창을 X 버튼으로 닫기 (§6.1로 끈다).
- 결과 불명 알림이 떠 있는 종목을 키움 앱에서 손으로 주문 (시스템 주문으로 잘못 인식될 수 있다).
- 시스템이 쓰는 모의 계좌에 키움 앱으로 손 주문 (대조 불일치 K4가 걸린다).
- 설정 파일(`.env`, `.env.paper`)의 내용을 대화·텔레그램에 붙여 넣기.
