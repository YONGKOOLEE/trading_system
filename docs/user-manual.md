## 0. 용어
| 말 | 뜻 |
|---|---|
| 자동 운영(autopilot) | 하루 전체를 맡는 프로그램. 시작 점검 → 매매 프로그램(run) 실행 → K8 자동 재개 → 15:45 종료·집계·백업 → 일일 요약 |
| run | 실제로 시세를 보고 주문을 내는 매매 프로그램 |
| 시작 점검(preflight) | 키움 접속·조회·시계 오차를 확인하는 점검. 통과해야 run이 켜진다 |
| 대조 | 키움의 주문·체결·잔고와 시스템 기록이 같은지 비교하는 것. 같으면 MATCH |

| 예약 작업 | Windows 작업 스케줄러에 등록해 평일 아침 자동으로 켜지게 하는 것 |
| 종료 코드 | 자동 운영이 끝날 때 남기는 숫자 0·1·2·3. 작업 스케줄러 화면에서 볼 수 있다 (§3.1) |

## 2. 처음 한 번 — 무인 전환 준비 (10-12 월요일 전, 사용자)
5단계를 차례로 한다. 1·3단계는 **관리자 권한**이 필요하다.

**관리자 권한 PowerShell 여는 법**: 시작 메뉴에서 "Windows PowerShell"을 검색 → **오른쪽 클릭 → "관리자 권한으로 실행"** → "이 앱이 디바이스를 변경하도록 허용하시겠어요?"에 "예". 창 제목에 "관리자"가 보이면 맞다.
**일반 PowerShell 여는 법**: 시작 메뉴에서 "Windows PowerShell"을 그냥 클릭.

### 2.1 1단계 — Windows 시간 서버를 `time.kriss.re.kr`(한국표준과학연구원)로
왜: 시스템은 시계가 1초 넘게 틀리면 시작을 거부하고(시작 점검), 장중에는 K6로 주문을 막는다. 시스템이 시계를 재는 서버가 `time.kriss.re.kr`이므로 Windows도 같은 서버에 맞춘다. 06:40 예약 작업(`w32tm /resync`)은 여기서 정한 서버로 맞춘다.

**방법 A — 화면으로**
1. 키보드 `Windows 키 + R` → 나온 "실행" 칸에 `timedate.cpl` 입력 → Enter.
2. "날짜 및 시간" 창 → **"인터넷 시간"** 탭 → **"설정 변경..."** (관리자 확인 창이 뜨면 "예").
3. "인터넷 시간 서버와 동기화" 체크 → "서버" 칸의 글자를 지우고 `time.kriss.re.kr` 입력 → **"지금 업데이트"**.
4. 기대 결과: 창 아래에 "time.kriss.re.kr와(과) 동기화되었습니다" 비슷한 문구와 시각. → "확인" → "확인".
5. "오류가 발생했습니다"가 나오면 "지금 업데이트"를 한 번 더 누른다. 그래도 안 되면 방법 B.

**방법 B — 관리자 권한 PowerShell에서 세 줄** (한 줄씩 붙여 넣고 Enter)
```
w32tm /config /manualpeerlist:"time.kriss.re.kr,0x8" /syncfromflags:manual /update
w32tm /resync
w32tm /query /source
```
기대 결과:
- 첫째·둘째 줄: "명령을 완료했습니다." (영문 Windows면 `The command completed successfully.`) — 한글 문구는 [확인 필요].
- 셋째 줄: `time.kriss.re.kr,0x8`
- 둘째 줄에서 "서비스가 시작되지 않았습니다"가 나오면 `net start w32time`을 실행한 뒤 둘째·셋째 줄을 다시.
- 뜻: 첫째 줄은 "시간 서버를 time.kriss.re.kr로 지정"(`,0x8`은 일반 클라이언트 방식으로 묻는다는 표시), 둘째 줄은 "지금 맞추기", 셋째 줄은 "지금 어느 서버를 쓰는지 보기".

### 2.2 2단계 — 루트 설정 파일의 모드 줄 확인 (일반 PowerShell)
왜: 예약 작업에는 창에서 넣던 `$env:TRADE_MODE='PAPER'`가 없다. 자동 운영은 `.env` 파일의 한 줄로 모드를 확인하고, 없거나 PAPER가 아니면 시작을 거부한다(그날 매매 없음, 위험 아님).
```
cd C:\AI\trading_system\trading_system
Select-String -Path .\.env -Pattern '^TRADE_MODE='
```
기대 결과: `.env:숫자:TRADE_MODE=PAPER` 한 줄. 아무것도 안 나오거나 PAPER가 아니면 메모장으로 `.env`를 열어 그 줄만 `TRADE_MODE=PAPER`로 고치거나 맨 아래에 추가한다(다른 줄은 건드리지 않는다. 내용을 대화·텔레그램에 붙이지 않는다).

### 2.3 3단계 — 예약 작업 등록 (관리자 권한 PowerShell)
```
cd C:\AI\trading_system\trading_system
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\schedule-register.ps1
```
기대 결과:
- `등록 완료 (사용자: ...)`
- 작업 2개 `TradingSystem-PAPER-ClockSync`, `TradingSystem-PAPER-Autopilot`이 `Ready`
- 다음 실행 시각이 다음 평일 06:40·06:45
- `이미 등록된 작업`이라고 나오면 이미 등록된 것이다(아무것도 바뀌지 않음).

### 2.4 4단계 — 실행 계정 확인 (일반 PowerShell)
왜: 작업이 내 계정이 아닌 `SYSTEM`으로 등록되면 `.venv`·텔레그램 설정을 읽지 못한다.
```
whoami
Get-ScheduledTask -TaskName 'TradingSystem-PAPER-*' | Select-Object TaskName, State, @{n='User';e={$_.Principal.UserId}}
```
기대 결과: 첫 줄은 내 Windows 사용자(예: `PC이름\user`). 그 아래 표 두 줄 모두 `State`가 `Ready`, `User`가 첫 줄과 같은 사용자(앞의 `PC이름\`은 없을 수도 있다). `SYSTEM`이면 §6.4로 해제하고 Claude에게 알린다.

### 2.5 5단계 — PC 설정 (화면으로)
1. **Windows 업데이트 사용 시간**: `Windows 키 + I`(설정) → "Windows 업데이트" → "고급 옵션" → "사용 시간" → "사용 시간 조정"을 **"수동"** → 시작 **오전 6:00**, 종료 **오후 6:00**. 이 시간에는 업데이트 때문에 자동으로 재시작하지 않는다.
2. **절전 끔**: 설정 → "시스템" → "전원"(노트북은 "전원 및 배터리") → "화면, 절전 및 최대 절전 시간 제한" → "절전 모드로 전환"(전원 연결 시) → **"안 함"**.
3. 화면 잠금은 괜찮다. **로그아웃·재부팅 뒤 로그인하지 않으면 실행되지 않는다.**

메뉴 이름은 Windows 버전에 따라 조금 다를 수 있다. 못 찾으면 그 화면을 Claude에게 말로 설명하면 된다.

### 3.1 자동 운영 결과 보기 — 종료 코드
자동 운영은 끝날 때 숫자 하나(종료 코드)를 남긴다.

| 코드 | 뜻 | 텔레그램에서 보이는 것 | 할 일 |
|---|---|---|---|
| 0 | 정상(휴장일 포함) | 일일 요약("확인 필요" 없음) 또는 "휴장일" | 없음 |
| 1 | 하루를 돌았으나 문제 있음 | 일일 요약 끝에 "확인 필요: …" | §3.2 |
| 2 | run을 시작하기 전에 거부·중단 — **그날 매매 없음** | "자동 운영 거부…", "시작 점검 실패…" 등(§4 ⑨). 설정 오류면 텔레그램도 없을 수 있음 | §4 ⑨ |
| 3 | run을 시작한 뒤 중단, 또는 처리하지 못한 오류 | 긴급 "run 프로세스가 종료됨", "자동 운영 오류…", "자동 운영 예외 종료…" | §4 ⑥ |

**보는 곳 1 — 작업 스케줄러 화면**: 시작 메뉴에서 "작업 스케줄러" 실행 → 왼쪽 "작업 스케줄러 라이브러리" 클릭 → 가운데 목록의 `TradingSystem-PAPER-Autopilot` 행 → **"마지막 실행 결과"** 칸. 괄호 안 숫자만 본다: `(0x0)`=0, `(0x1)`=1, `(0x2)`=2, `(0x3)`=3. 앞의 설명 문구는 Windows가 붙이는 일반 문구라 무시한다. `(0x41301)`은 "지금 실행 중", `(0x41303)`은 "아직 한 번도 실행되지 않음". 그 밖의 숫자는 Claude에게 알린다.

**보는 곳 2 — 일반 PowerShell**:
```
Get-ScheduledTaskInfo -TaskName 'TradingSystem-PAPER-Autopilot' | Select-Object LastRunTime, LastTaskResult, NextRunTime
```
기대 결과: `LastTaskResult`가 0·1·2·3 중 하나. `267009`는 지금 실행 중, `267011`은 아직 실행되지 않음.

**사유가 적힌 기록 파일** (`C:\AI\trading_system\trading_system\var\paper\logs\` 폴더, 비밀값은 가려서 기록됨)
| 파일 | 내용 |
|---|---|
| `autopilot-YYYYMMDD.log` | 자동 운영의 하루 기록. 거부·오류 사유가 여기 먼저 남는다 |
| `run-console-YYYYMMDD.log` | run(매매 프로그램)의 출력 |
| `alerts-fallback-autopilot.log` | 텔레그램으로 끝내 못 보낸 자동 운영 알림 |
| `autopilot-fatal.log` | 하루 기록조차 못 쓴 채 오류로 끝난 경우(오류 종류만) |
| `fatal.log` | run 쪽 심각한 오류 |

오늘 자동 운영 기록의 마지막 40줄 보기 (일반 PowerShell):
```
cd C:\AI\trading_system\trading_system
Get-Content ".\var\paper\logs\autopilot-$(Get-Date -Format yyyyMMdd).log" -Encoding UTF8 -Tail 40
```
텔레그램으로 못 보낸 알림이 있었는지 보기:
```
cd C:\AI\trading_system\trading_system
Test-Path .\var\paper\logs\alerts-fallback-autopilot.log
```
기대 결과: `False`면 없음. `True`면 Claude에게 "알림 실패 기록 봐 줘"라고 한다(에이전트가 직접 읽는다).

### 3.2 일일 요약의 "확인 필요" 줄
일일 요약 끝에 `확인 필요: …`가 붙으면 종료 코드는 1(또는 3)이다. 줄을 그대로 Claude에게 보낸다. 뜻은 다음과 같다.

| 문구 | 뜻 | 위험 | 할 일 |
|---|---|---|---|
| K8 자동 재개 못 함 | 08:55까지 K8이 안 풀려 그날 매매 없었음 | 없음(주문 안 함) | §4 ② 행 사유 확인 |

### 4.2 K3(결과 불명) 해소 — 퇴근 후 PC에서
왜 PC인가: 결과 불명 확정과 K3 재개는 원격(텔레그램)으로 할 수 없다. K3가 걸려 있으면 다음 날 아침 자동 운영도 K8을 자동으로 풀지 않으므로(사람 확인 정지) 해소 전에는 매매가 없다.

모든 명령은 일반 PowerShell에서, 먼저 `cd C:\AI\trading_system\trading_system`.

1. **상태 보기**
   ```
   .venv\Scripts\python scripts\status.py --mode PAPER
   ```
   기대 결과: "해제되지 않은 정지"에 `K3 … 종목=005930`(예), "결과 불명 의도: 1건"과 그 아래 `의도ID 종목 방향 수량` 한 줄. 이 출력을 Claude에게 보낸다(계좌번호·금액 없음).
2. **키움 앱(모의투자) 확인**: 주문체결내역에서 그 종목·방향·수량·시각의 주문이 있는지 본다. 있으면 주문번호를 적어 둔다. 앱에서 손으로 주문·취소하지 않는다.
3. **결과 확정** ("접수됨 — 주문번호 ○○" 또는 "접수 안 됨"): **[확인 필요] 현재 이 확정을 사람이 실행할 도구(scripts 명령)가 없다.** 시스템 안에는 확정 기능(로컬 전용 명령 CONFIRM_UNKNOWN)이 있지만 그것을 기록하는 PC 도구가 아직 만들어지지 않았다. Claude는 확정을 대신 하지 않는다(A-079). → 2번 결과를 Claude에게 알리고 도구 추가 여부를 결정한다. 확정 전까지 K3는 풀리지 않는다(그동안 매매 없음, 위험 확대 없음).
4. **확정이 끝난 뒤 — 새 대조 요청과 K3 재개 요청** (두 줄, 순서대로)
   ```
   .venv\Scripts\python scripts\reconcile-resolve.py --mode PAPER --account KR-PAPER-01 --run
   .venv\Scripts\python scripts\resume.py --mode PAPER K3
   ```
   기대 결과: `RECONCILE 요청 기록: local-…`, `재개 요청 기록: local-… (판정은 본 프로세스, 결과는 status로 확인)`.
   - 저녁에는 run이 꺼져 있으므로 이 명령들은 **기록만** 되고, 다음 날 아침 run이 시작할 때 차례로 처리된다(3일차 아침 `RESUME K1` 처리와 같은 방식). K3는 "결과 불명 의도 0건 + 확정 뒤 새 대조 일치"일 때만 풀린다.
   - K3가 08:55 전에 풀리면 자동 운영이 K8 자동 재개를 이어 간다. 아침에 `/status`로 K3가 사라졌는지 본다.
   - 이 순서로 다음 날 아침 K3가 실제로 풀리는지는 아직 시험하지 않았다 **[확인 필요]**. 안 풀리면 그날은 매매 없음 → Claude에게.
   - 새 대조에서 불일치(K4)가 나오면 해소 방법은 사용자가 고른다(Claude가 선택지를 설명).

## 5. 원격
### 5.1 텔레그램 명령 (매매 프로그램 봇)
| 명령 | 하는 일 | 확인 코드 |
|---|---|---|
| `/review` | 오늘 체결·정지·결과 불명·불일치·마지막 대조 (계좌번호·금액 없음) | 없음 |
| `/status` | 정지 목록·KILL 파일·결과 불명·불일치 건수 | 없음 |
| `/kill [사유]` | K1 긴급 정지 (즉시) | 없음 |
| `/resume K1`·`/resume K2`·`/resume K4`·`/resume K8` | 정지 재개. K4·K8은 그 자리에서 새로 대조해 완전 일치할 때만 | 필요 |
| `/reconcile` | 즉시 대조, 결과 회신 | 필요 |
| `/exit 종목 수량`·`/reduce 종목 수량` | 청산·감액 요청 (예: `/exit 005930 1`, 중앙 게이트를 거침) | 필요 |
| `/cancel 주문키` | 미체결 주문 취소 요청 (주문키는 `/review`·Claude에게 확인) | 필요 |
| `/confirm 코드` | 위 "필요" 명령의 답으로 온 코드를 60초 안에 보내 실행 확정 | — |

- 원격으로 **풀 수 없는** 정지: K3(결과 불명)·K7(저장 실패)·K9(전략)·실행기가 건 K4 → PC에서. 결과 불명 확정·불일치 해소(`reconcile-resolve`)도 PC에서만.
- 저절로 풀리는 정지: K5·K6·K10·K11(조건이 정상화되면).
- run이 꺼져 있는 동안(밤·휴일) 보낸 명령은 실행되지 않는다. 시작 직후 "꺼져 있던 동안 보낸 명령이라 실행하지 않았습니다"가 오면 필요할 때 다시 보낸다.

### 5.2 Claude 원격 (분석·개발 지시)
1. 집 PC VS Code의 Claude 대화창에 `/remote-control` 입력 (출발 전).
2. 회사에서 브라우저 claude.ai/code 또는 휴대폰 Claude 앱 Code 탭 → 집 PC 세션 선택.
3. PC나 VS Code가 꺼지거나 30분가량 네트워크가 끊기면 연결이 끊긴다 → 퇴근 후 다시 `/remote-control`.

대화로 지시하면 에이전트가 할 수 있는 PAPER 운영 명령(A-079): 시작·정지·정지 재개 명령 기록·status·paper-review·backup. **하지 않는 것**: LIVE 일체, 실전 주문, 불일치 해소 방법 선택, 결과 불명 확정, KILL 파일 삭제, 예약 작업 등록·해제, 지시 없는 시작·재개.

### 6.5 PC를 재부팅했을 때
재부팅 뒤 **로그인만 하면** 다음 평일 06:45에 다시 실행된다. 장중에 재부팅됐다면 그날 run은 멈춘 상태다(자동 재시작 없음). 그날은 매매 없음으로 두는 것이 기본이다. 다시 켜고 싶으면 §6.3(08:55 이후에는 자동 운영이 "늦은 시작"으로 거부한다). 재시작 직후에는 K8이 걸리고, 대조가 끝난 뒤에야 주문이 다시 가능하다.

## 7. 정지 종류
"막힘"·"허용"은 시스템 코드(`domain/halts.py`) 기준이다. **모든 정지는 신규 매수·증액을 막는다(K9·K10은 그 전략·종목만).** 어떤 정지도 보유 주식을 자동으로 팔지 않는다.

| 정지 | 뜻 | 정지 중 허용되는 것 | 14:30 전략 매도 | 풀리는 방법 | 원격 재개 |
|---|---|---|---|---|---|
| K1 | 수동 긴급 정지 | 사람의 청산·감액·취소(`/exit`·`/reduce`·`/cancel`) | **막힘** | 사용자 재개 (자동 운영은 풀지 않음) | 가능 |
| K2 | 일일 손실 한도 | 매도·감액·취소 전부 | 나감 | 다음 일일 기준 시각 뒤 사용자 재개 | 가능 |
| K3 | 결과 불명 주문 | **결과 불명 종목이 아닌 다른 종목의 취소만**. 청산·감액은 사람 요청도 막힘 | **막힘** | 사람이 결과 확정 → 새 대조 일치 → 사용자 재개 (§4.2) | 불가(PC만) |
| K4 | 대조 불일치 | 취소만 | **막힘** | 불일치 해소·대조 일치 뒤 재개 | 새 대조 일치 시(대조기가 건 K4만) |
| K5 | 브로커 연결 끊김 | 없음 | 막힘 | 연결 복구 + 대조로 자동 | 자동 |
| K6 | 시계 오차 | 사람의 청산·감액·취소만 | **막힘** | 시계 정상화로 자동(10분마다 확인) | 자동 |
| K7 | 저장 실패 | 없음 | 막힘 | 무결성 점검 뒤 사용자 재개 | 불가(PC만) |
| K8 | 재시작 복구 대기 | 없음 | 막힘 | 매일 아침 자동 재개(조건 충족 시). 장중 재발은 사람이 재개(§4 ⑪) | 새 대조·복구 조건 충족 시 |
| K9 | 전략 중지 | 다른 전략은 영향 없음. 그 전략의 취소·사람 요청. "교체" 중지면 그 전략의 매도 신호도 허용 | 교체면 나감 | 전략 상태 전환(승인 필요). 지금은 v1 교체 표시 1건이 남는 것이 정상 | 불가(PC만) |
| K10 | 시세 데이터 품질 | 그 종목(전체 지연이면 모든 종목)의 신규 매수만 막음. 매도는 시세 확인 규칙(G11)으로 판정 | 시세 규칙에 따름 | 자동 | 자동 |
| K11 | 알림 3번 연속 실패 | 매도·감액·취소 전부 | 나감 | 알림 전송 성공으로 자동 | 자동 |

여러 정지가 함께 걸리면 **모두가 허용하는 것만** 나간다(가장 엄격한 쪽).

## 8. 전략 바꾸기
전략 변경은 **승인이 필요한 작업**이라 혼자 하지 않는다. 순서:
1. Claude에게 원하는 전략을 말한다 → 에이전트가 전략 문서·백테스트를 만든다.
2. 사용자가 백테스트 결과를 보고 승인한다.
3. **보유 0건인 날 저녁**에 바꾼다(보유는 전략 버전 사이에 넘어가지 않는다). 에이전트가 설정을 바꾸고, 사용자가 실행할 `strategy.py` 명령을 사본으로 미리 시험한 뒤 안내한다.
4. 다음 날 아침 텔레그램에 K9(이전 버전 중지) 경고가 오는 것은 정상이다.

## 9. 하지 말 것
- run이 돌고 있는 동안 시작 점검(preflight)이나 run을 한 번 더 실행.
- 실행 창을 X 버튼으로 닫기 (§6.1로 끈다).
- 결과 불명 알림이 떠 있는 종목을 키움 앱에서 손으로 주문 (시스템 주문으로 잘못 인식될 수 있다).
- 시스템이 쓰는 모의 계좌에 키움 앱으로 손 주문 (대조 불일치 K4가 걸린다).
- 설정 파일(`.env`, `.env.paper`)의 내용을 대화·텔레그램에 붙여 넣기.

## 10. 아직 확인되지 않은 것 (2026-10-09 기준)
- **예약 작업 경로**(창 없이, `.env`의 모드 줄로 시작)는 아직 실제로 돈 적이 없다. 첫 예약 실행일 2026-10-12(월) 06:50 텔레그램과 §3.1 종료 코드로 확인한다. 15:45 종료·집계·백업·요약은 3일차(10-08)에 사용자가 직접 실행한 자동 운영으로 1회 정상 확인했다.
- **결과 불명 확정 도구 없음**: K3를 풀려면 사람이 결과를 확정해야 하는데, 그 확정을 기록하는 PC 도구(scripts)가 아직 없다(§4.2 3번). 지금까지 결과 불명 0건이지만, 생기면 확정 도구가 마련될 때까지 매매가 멈춘다(위험 확대는 없음).
- §4.2 4번처럼 저녁에 기록한 대조·K3 재개 요청이 다음 날 아침 순서대로 처리돼 K3가 풀리는지 시험하지 않았다.
- **일일 기준 기록 손상**(§4 ⑫) 복구 절차가 아직 없다. 손상되면 paper-review(집계)도 실패할 수 있다.
- 12월 "다음 해 달력 없음" 경고는 달력을 만들 때까지 매일 반복된다(알려진 불편, 위험 아님).
- 작업 스케줄러 실행 시간 상한(11시간)에 걸렸을 때 run이 함께 끝나는지 실측하지 않았다(정상 흐름은 16:30 전에 끝난다).
- §2.1 방법 B 명령의 한글 결과 문구, §2.5 메뉴 이름은 이 PC에서 확인하지 않았다(명령 형식은 Windows 표준 `w32tm` 형식).
